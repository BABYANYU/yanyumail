# 使用说明

## 访客侧

| 步骤 | 表现 |
| --- | --- |
| 打开 Bot 发任意消息 | 收到算术验证题（内联按钮） |
| 答对 | 提示“验证成功，有效期 7 天”，随后可正常留言 |
| 答错 | 可重试，共 3 次机会；超限需等待冷却后重新 `/start` |
| 验证前发送的消息 | **不会被转发，也不会在通过后补发** |
| 支持内容 | 文字、图片、语音、视频、文件，以及 Telegram 允许复制的其他类型 |
| 发送频率 | 每分钟约 20 条，超出后丢弃 |

访客不会看到管理员账号，也不会看到其他人的消息。

## 管理员侧

所有操作都在**你自己与 Bot 的私聊窗口**内完成。

| 操作 | 方法 |
| --- | --- |
| 接收消息 | 对方每条消息都会转成一条副本，附带首次联系时的身份卡 |
| 回复 | **引用对应消息**，直接发送文字或媒体 |
| 不引用直接发 | 不发送，提示“请引用对应联系人的消息” |
| `/block` | 引用后发送，拉黑该联系人，之后其消息全部丢弃 |
| `/unblock` | 引用后发送，解除拉黑 |
| `/trust` | 引用后发送，永久免验证（仍受基本限频） |
| `/untrust` | 引用后发送，取消信任并清除验证状态 |
| `/info` | 引用后发送，查看昵称、用户名、用户 ID |
| `/help` | 显示管理帮助 |

## 设计取舍

| 取舍 | 原因 |
| --- | --- |
| 必须引用回复 | 多个联系人共用同一窗口，靠引用定位收件人，避免误发 |
| 不做“自动回复最后一人” | 一条错发可能泄露给错误对象，风险高于便利 |
| 验证前不转发 | 广告不应占用管理员注意力，也不应进入通知流 |
| 验证后仍限频 | 人机验证只挡自动化，挡不住真人刷屏 |
| 通知不带原文 | 失败提示只说明发送失败，不复述对方内容 |

## 已知限制

- KV 最终一致：极端并发下可能重复转发或限频计数偏差，**不是严格幂等**。
- 路由保留 30 天：引用超过 30 天的旧消息会提示找不到联系人。
- 受 Telegram 保护的内容（禁止保存/转发）无法复制，转交会失败并提示。
- 语音、视频等大文件由 Telegram 直接转发，不经 Worker 存储，但仍受 Bot API 限制。
- Bot 私聊**不是端到端加密**，等同于普通云端聊天，敏感信息不要发。
