# 使用说明

## 访客侧

| 步骤 | 表现 |
| --- | --- |
| 打开 Bot 发任意消息 | 收到算术验证题（内联按钮） |
| 答对 | 提示“验证通过，请简述来意。”，随后可正常留言 |
| 答错 | 可重试，共 3 次机会；超限提示“验证次数过多，请稍后重试。” |
| 验证前发送的消息 | **不会被转发，也不会在通过后补发** |
| 验证有效期 | 通过后 **24 小时内免验证**；超过 24 小时再联系需重新答一次 |
| 支持内容 | 文字、图片、语音、视频、文件，以及 Telegram 允许复制的其他类型 |
| 发送频率 | 每分钟约 20 条，超出后丢弃 |

验证是**按时间窗口**，不是每条消息都验。访客不会看到管理员账号，也看不到其他人的消息。

## 管理员侧

所有操作都在**你自己与 Bot 的私聊窗口**内完成。

### 身份卡按钮

某人首次通过验证并留言时，会收到一张**身份卡**，含昵称、用户名、用户 ID，下方四个按钮：

| 按钮 | 作用 |
| --- | --- |
| 拉黑 | 该联系人消息静默丢弃，不通知你 |
| 解封 | 解除拉黑 |
| 信任 | 永久免验证（仍受限频） |
| 信息 | 重新显示身份与当前状态 |

按钮只对管理员有效，非管理员点击无效。身份卡只发一次；之后往上翻仍可点击。

### 回复与命令

| 操作 | 方法 |
| --- | --- |
| 接收消息 | 对方每条消息转成一条副本，附在身份卡之后 |
| 回复 | **引用对应消息**，直接发送文字或媒体 |
| 不引用直接发 | 不发送，提示“请引用对应联系人的消息” |

引用消息后可用命令（括号内为短别名）：

| 命令 | 作用 |
| --- | --- |
| `/block`（`/b`） | 拉黑 |
| `/unblock`（`/ub`） | 解封 |
| `/trust`（`/t`） | 永久免验证 |
| `/untrust`（`/ut`） | 取消信任并清除验证 |
| `/info`（`/i`） | 查看身份与状态 |
| `/help` | 显示帮助 |

## 设计取舍

| 取舍 | 原因 |
| --- | --- |
| 必须引用回复 | 多个联系人共用同一窗口，靠引用定位收件人，避免误发 |
| 不做“自动回复最后一人” | 一条错发可能泄露给错误对象，风险高于便利 |
| 验证前不转发 | 广告不应占用管理员注意力，也不应进入通知流 |
| 验证后仍限频 | 人机验证只挡自动化，挡不住真人刷屏 |
| 失败提示不带原文 | 提示只说明发送失败，不复述对方内容 |

## 已知限制

- KV 最终一致：极端并发下可能重复转发或限频计数偏差，**不是严格幂等**。
- 路由保留 30 天：引用超过 30 天的旧消息会提示找不到联系人；此时可按用户 ID 处理。
- 拉黑后对方无任何提示，可能以为 Bot 故障。
- 受 Telegram 保护的内容（禁止保存/转发）无法复制，转交会失败并提示。
- Bot 私聊**不是端到端加密**，等同于普通云端聊天，敏感信息不要发。
