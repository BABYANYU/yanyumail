# 偏好与约定

记录本项目的个人偏好，供后续修改时保持一致。

## 文案与命名

| 项目 | 约定 |
| --- | --- |
| 品牌写法 | 用 **Yanyu**，不使用“烟雨”作为对外英文标识的替代 |
| Bot 名称 | `YanyuMail`，大小写固定为这一种写法 |
| 公开介绍 | 当前为「请联系 Yanyu 前完成验证」 |
| 文案风格 | **简约、专业、正式**；不要“欢迎”“请勿刷屏”等口语或说教式表述 |
| 避免 | 未经证实的宣传词（如“官方”“安全加密”“100% 稳定”） |
| 不写 | 功能罗列式介绍；公开介绍保持一句话 |

## 交互偏好

| 项目 | 约定 |
| --- | --- |
| 收信位置 | 直接在 Bot 私聊窗口，**不建后台群、不用话题分组** |
| 回复方式 | **引用消息回复**；明确优于便利，不做“自动发给最后一人” |
| 验证 | 必须有人机验证，否则广告会直接进入管理员通知流 |
| 验证前 | 不转发、不补发、不逐条通知管理员 |
| 打扰控制 | 拦截、限频、失败都不应反复打扰管理员 |

## 技术偏好

| 项目 | 约定 |
| --- | --- |
| 托管 | Cloudflare Workers，不用 VPS、不用 Docker |
| 成本 | 只用免费额度，不主动开通付费；若额度不足，先降频而非升级 |
| 依赖 | 尽量零依赖，单文件 Worker，便于审查和迁移 |
| 数据 | KV 只存路由与管理必需状态，带 TTL，不做长期聊天存档 |
| 安全 | Webhook 必须校验 secret；只有管理员可执行管理命令 |
| 语言 | 面向用户的中文文案保持书面、克制 |

## 协作约定

| 项目 | 约定 |
| --- | --- |
| 仓库 | **私有**。含管理员 ID、账号资源标识与运维细节，不公开 |
| 敏感信息 | Token、Secret、真实管理员 ID、账号 ID 一律不入库 |
| 变更流程 | 改代码 → `npm test` → 部署 → 用另一个账号实测双向收发 |
| 交接 | 后续可交 Codex 维护，入口见 `HANDOFF.md` |
